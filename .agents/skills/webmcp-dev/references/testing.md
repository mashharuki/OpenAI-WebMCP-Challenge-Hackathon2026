# WebMCP テストガイド（調査時点のスナップショット）

> `dev.classmethod.jp` の実践記事を基にした調査時点（2026-08）のスナップショット。Chromeのバージョン番号・フラグ名・拡張機能名は変わりうるので、事前に `chrome://flags` を検索して現在の名称を確認すること。

## 前提条件

1. **Chrome 146以降**（記事執筆時点の要件。要件バージョンは上がっていく前提で `chrome://settings/help` で現在のバージョンを確認する）
2. `chrome://flags#webmcp-for-testing` を検索し、**Enabled** にして再起動する
3. **ページは必ずHTTPサーバー経由で配信する**。`file://` プロトコルでは動作しない。ローカルなら:
   ```bash
   python3 -m http.server 8080
   # または
   npx serve -p 8080
   ```

## 有効化の確認

DevToolsのコンソールで以下を実行し、`true` が返るか確認する（`references/api-reference.md` の namespace 食い違いに注意し、両方試す）:

```javascript
"modelContext" in navigator
"modelContext" in document
```

## 手動テスト: Model Context Tool Inspector 拡張機能

1. Chromeウェブストアから "Model Context Tool Inspector" 拡張機能を導入する。
2. 対象ページを開いた状態で拡張機能を起動すると、そのページが登録しているツール一覧がドロップダウンに表示される。
3. テストしたいツールを選び、JSON形式で引数を入力する（例: `{"a": 10, "b": 3, "operation": "add"}`）。
4. "Execute Tool" をクリックし、返り値・エラーの有無をパネルとブラウザコンソールの両方で確認する。

この拡張機能は「現在ページにどんなツールが公開されているか」を可視化する実質唯一の手段（`navigator`/`document` から登録済みツール一覧を直接列挙するAPIは調査時点で確認できていない）。テスト時は必ずこれで期待通りのツールが期待通りの内容で登録されているかをまず目視確認する。

## エージェント駆動テスト: 「Interact with the page」機能

同拡張機能には自然文プロンプトを渡すとGemini APIベースでエージェントが自律的にツールを選んで実行する機能がある。例:

> 「Johnに挨拶して、それから50と10を掛け算してください」

これで期待通りのツールが選ばれない・違うツールが呼ばれる場合、**それは実装のバグではなく `description` の書き方の問題であることが多い**。ツール名や説明文がエージェントにとって曖昧・類似ツールと区別しづらい、という兆候なので、`SKILL.md` フェーズ1の設計ガイドに戻って命名・粒度を見直す。

## テストマトリクス（最低限これは網羅する）

各ツールについて:

| ケース | 確認内容 |
|---|---|
| 正常系（妥当な引数） | 期待通りの結果が返る |
| 不正な引数（型不一致・必須項目欠落） | `inputSchema` のバリデーションでエラーになる、あるいはアプリ側で適切にハンドリングされる（クラッシュしない） |
| 連続/多重実行 | 短時間に複数回呼ばれても状態が壊れない（特に状態変更系ツール） |
| クロスオリジン呼び出し（`exposedTo` 設定時のみ） | 許可オリジン以外からは呼び出せない／見えない |
| エージェント経由の自然文呼び出し | 「Interact with the page」機能で意図通りのツールが選ばれる |

破壊的操作（削除・購入確定など）は、上記に加えて「確認なしに即実行されないか」を必ず確認する。WebMCPは human-in-the-loop 前提の設計なので、確認フローを省略する実装は仕様の意図から外れる。

## 既知のハマりどころ

- 宣言的API（`<form>` へのアノテーション）はまだ機能していない環境が多い。動かなくても実装ミスとは限らず、仕様側の未成熟によるものの可能性が高い。
- サイトの利用規約でボット/自動操作を禁止している場合、WebMCP経由であっても自律エージェントにページを操作させることが規約違反になりうる、と実践記事の著者は指摘している。自社サイト以外（特に決済・会員制サービスなど）にWebMCPを実装する/対象にする場合は、この観点も設計レビューに含めること。
