# WebMCP セキュリティレビューガイド（調査時点のスナップショット）

> `developer.chrome.com/docs/ai/webmcp/secure-tools` の内容を基にした調査時点（2026-08）のスナップショット。細かい数値制限や推奨事項は今後変わる可能性があるため、本番リリース前に一次情報を再確認すること。

## なぜ重要か

WebMCP はページの機能をブラウザ内AIエージェントに直接渡す。ツールの `description`・パラメータの説明・**`execute` の返り値**はすべて最終的にLLMへの入力になり得る。つまり、これらのどこかにユーザー生成コンテンツや外部データが混ざると、そのままプロンプトインジェクションの経路になる。Chrome公式ドキュメントも「LLMは確率的に動作するため、いかなる対策も完全な保証にはならない」と明言している — **多層防御**が前提。

## リスク: プロンプトインジェクション

攻撃者は以下の経路で悪意のある指示を埋め込める:

- ツールの `description` / パラメータの `description` 自体（ページ実装者が意図せず外部入力を混ぜ込んだ場合）
- ツールの実行結果（`execute` の返り値）に含まれる、ユーザー投稿やサードパーティAPIのレスポンスなどの外部由来コンテンツ

## 対策1: `annotations.untrustedContentHint` を使う

ツールの入出力にユーザー生成コンテンツや外部データが含まれる場合は `untrustedContentHint: true` を付ける。エージェント側にそのコンテンツを「指示」ではなく「データ」として扱うよう伝えるシグナルになる。

```javascript
execute: async ({ productId }) => {
  const review = await fetchUserReview(productId); // 外部・ユーザー由来
  return {
    content: [{ type: "text", text: review }],
    // このツールは常にuntrusted contentを返すので登録時点でヒントを付けておく
  };
}
```

## 対策2: `annotations.readOnlyHint` を使う

非破壊的（読み取り専用）なツールには `readOnlyHint: true` を付ける。ホスト（エージェント側UI）はこれを見て、確認プロンプトを出すかどうかの判断材料にする。逆に状態を変更するツール（購入確定、削除、投稿の公開など）はこのヒントを付けず、ホスト側の確認フローに乗るようにする。

**ただし `readOnlyHint` を外すだけでホストが必ず確認UIを出してくれる保証はない**（確認/パーミッションのUX自体が仕様上まだ未確定の領域 — `references/api-reference.md` の未解決issue参照）。取り返しのつかない操作（決済確定・アカウント削除・公開投稿など）については、ホストの確認フローだけに委ねず、アプリ側でも追加の防御を検討する。例えば「削除」ツールに `confirm: true` のような明示的な確認パラメータを必須にする、破壊力の大きい操作は `execute` 内で二段階確認を要求する、といった形。これはホストの実装がまだ揃っていない現状に対する多層防御であり、恒久的な設計方針というより「仕様が成熟するまでの補強」と位置付ける。

## 対策3: `exposedTo` で公開範囲を絞る

- デフォルトは同一オリジンのみに公開される。これを緩めてクロスオリジン公開する場合、**読み取り専用のツールは直接連携している信頼できるパートナーオリジンだけ**に絞る。
- **書き込み系・状態変更系のツール（例: `postComment` のような操作）は、特に厳格なアローリストにする**。安易に広いオリジン集合や `"*"` 的な緩い設定をしない。

## 対策4: 文字数制限を守る

読みやすさだけでなく、インジェクション面積を減らす防御でもある:

| 項目 | 上限 |
|---|---|
| ツール名 | 30文字 |
| パラメータ名 | 30文字 |
| ツールの説明文 | 500文字 |
| パラメータの説明文 | 150文字 |
| 個々の出力 | 1,500文字 |

長い説明が必要に感じたら、それはツールの責務が大きすぎるサインでもある。粒度を見直す（フェーズ1の設計ガイドを参照）。

## リリース前チェックリスト

- [ ] すべてのツールの `description` / パラメータ説明は、開発者自身が書いた文字列のみで構成されている（実行時に外部入力を混ぜ込んでいない）
- [ ] 外部データ・ユーザー生成コンテンツを返す可能性のあるツールには `untrustedContentHint: true` を付けた
- [ ] 破壊的・機微な操作を行うツールには `readOnlyHint` を付けていない、かつホスト側の確認フローを前提にした設計になっている
- [ ] クロスオリジン公開（`exposedTo`）が必要な場合、書き込み系ツールは最小限のアローリストになっている
- [ ] name / description / パラメータ説明 / 出力がすべて規定の文字数以内である
- [ ] 完全自律・ヘッドレスでの実行を想定していない（WebMCPは human-in-the-loop 前提の設計であることを踏まえ、重大操作は人間の確認を挟む）
